- The mouse wheel no longer stops working after it was first used while a blocked mod key was held
- A mod's blocked keys are released when the mod is unloaded or reloaded, instead of staying blocked
- Mod windows no longer flicker while a save loads, and blink less after Alt-Tab
- After a graphics crash (the game losing its graphics device), the mod windows now come back by themselves: they stay off for one launch as a precaution, and the log says so. Before, they stayed off until you edited modloader.ini. If your mod windows are still off from an earlier version, set Enabled=1 under [UI] in ModLoader\modloader.ini
- The log now records why the graphics device was lost and which step of a game icon copy failed, to help find the cause of a problem
- Mod overlay buttons can now be clicked while the build menu is open
- A fresh install opens a window titled Mod Loader Installed instead of Plugins Updated
- Mod windows no longer blink when the game gains or loses focus, and the log now records focus changes
- The Plugins Updated window is wider on large screens, so its notes no longer wrap into a thin column at 4K, and its title and Close button stay in view when the list is long
- After the mod loader updates itself, the Plugins Updated window lists the loader's release notes once, including the notes of releases you skipped
- The log no longer warns about every field on a build that has no map row of its own and is checked against another build's row; those differences are now Debug lines, and the game's value is still the one used
- PLUGIN_FIELD_ANY_SIZE now also works for a native member: the loader serves the offset and size from the map's row for your game build, so a plugin that only takes the member's address no longer has to know its size
- Plugins can now ask for the size of a game struct the game does not describe itself; the loader serves it from the version map's row for your game build, and turns the feature off on a build with no row. Structs the game does describe still use the game's own size, and a map row that disagrees is only logged. The compatibility report also lists every size a plugin asked for, and is now written on any launch where one did
- Plugins can now ask where the game puts a game function's parameters and how big its parameter block is, so a plugin calling a game function keeps working when a game update adds or moves a parameter
- That also works for a function of a Blueprint class that is not loaded yet (a UI widget, say): the plugin's feature waits, with a note in the log and the compat report instead of a warning, and starts once the game loads the class
- New image library: mods that show item or building pictures now get them from one place in the loader. A picture is read from the game only when a mod is about to show it, stored at 256 px at most, and kept under a 256 MB cap (less on a card with little video memory), with the least recently shown going first
- Mods read game pictures through one shared read that checks the game's texture before copying it, instead of each mod copying textures itself
- Pictures are saved to disk after the first time they are read, in ModLoader\image-cache, and load from there on later launches instead of from the game. At each launch the loader keeps the folder in use and the newest earlier one, removes the others, and trims the saved pictures to 256 MB, the ones used longest ago first. If a mod mounts a pak after the game has started, saved pictures are not used for the rest of that launch
- New Preload images from the game setting in the Settings tab (off by default): the loader reads the item and building pictures that mods list in the background, a few at a time, and pauses while a picture on screen is waiting or video memory is short
- New Clear image cache button in the Settings tab, under Preload images from the game, that deletes the saved pictures. Pictures already loaded stay for that session and the next launch saves them again
- Eight texture members the picture read needs are now rows of the version object map, for both game builds, and the loader's older icon copy reads them when the build has all of them. On a game build with no such rows, pictures from the image library show as placeholders
