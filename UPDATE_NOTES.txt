- The mouse wheel no longer stops working after it was first used while a blocked mod key was held
- A mod's blocked keys are released when the mod is unloaded or reloaded, instead of staying blocked
- Mod overlay buttons can now be clicked while the build menu is open
- New image library: mods that show item or building pictures can now get them from one place in the loader (plugin interface v76). A picture is read from the game only when a mod is about to show it, stored at 256 px at most, and kept under a 256 MB cap (less on a card with little video memory), with the least recently shown going first
- Mods that use the image library read game pictures through one shared read that checks the game's texture before copying it. Mods that still copy textures themselves keep working as before
- Pictures are saved to disk after the first time they are read, in ModLoader\image-cache, and load from there on later launches instead of from the game. A game update, or a mod pak that changed or moved in the load order, starts a new folder. At each launch the loader keeps the folder in use and the newest earlier one, removes the others, and trims the saved pictures to 256 MB, the ones used longest ago first. Pictures of textures the game makes while it runs are not saved. If a mod mounts a pak after the game has started, saved pictures are not used for the rest of that launch
- New Preload images from the game setting in the Settings tab (off by default): the loader reads the item and building pictures that mods list from the game in the background, one at a time, and pauses while a picture on screen is waiting or video memory is short
- New Clear image cache button in the Settings tab, under Preload images from the game, that deletes the saved pictures. Pictures already loaded stay for that session and the next launch saves them again
- Eight texture members the picture read needs are now rows of the version object map, for both game builds, and the loader's older icon copy reads them when the build has all of them. On a game build with no such rows, pictures from the image library show as placeholders
- A native member of a plain engine type that shares its name with a game class (FTexture beside UTexture) is now served from its version map row instead of being refused
